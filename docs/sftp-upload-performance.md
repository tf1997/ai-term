# SFTP 大目录上传与超时处理

2026-10-23

上传任务原先在前端、后端命令和系统 SFTP 进程中受整个任务 600 秒的限制。即使文件仍在传输，也会被停止，前端复用了连接超时文案。原生目录上传逐个处理文件；系统 SFTP 的进度行还会在 160 字符处截断，240 列终端中的字节数因此无法解析。

## 当前行为

- 原生目录上传扫描一次生成清单，父目录创建一次。文件数至少为 8 时，使用最多 4 条独立 SSH/SFTP 连接并行上传，连接在整个目录任务中复用。额外连接被服务器拒绝时使用已建立的连接继续。
- 每个工作线程复用 1 MiB 缓冲区；文件内容按块读取，内存用量不随文件大小增长。目录清单的内存用量随条目数增长。
- 上传、下载的后端超时改为连续 120 秒无进展，前端使用 150 秒无进度事件作为兜底。持续传输没有总时长上限。列目录、连接识别等非传输操作仍保留原来的总时限。
- 字节写入、文件关闭、目录创建和扫描推进会更新活动时间；扫描通知限制为约每 100 ms 一次。失败后不会切换路线重放写入，取消或超时会关闭工作连接。
- 单次原生传输 I/O 使用 120 秒超时，完成后恢复连接原来的超时。上传必须收到远端关闭文件的确认才算成功，最终成功前不会显示 100%。
- 系统 SFTP 备用路径也按传输进展延长进程时限，支持宽进度行和跨 PTY 数据块的进度解析，忽略字节数未变化的重复进度刷新。

## 验证与复现

前端运行 `npm run test:transfer`、`npm run test:ui` 和 `npm run build`。后端运行 `cargo test`。

真实协议测试使用隔离的 Python/Paramiko 回环服务，不连接业务服务器。将 `AI_TERM_SFTP_FIXTURE_PYTHON` 指向安装了 Paramiko 的 Python，在 `src-tauri/` 执行：

```text
cargo test --lib protocol_tests -- --ignored --test-threads=1 --nocapture
```

覆盖多文件与大文件完整性、嵌套目录和空文件、进度累计、连接数受限降级、持续传输超过初始时限、停滞超时与所有连接清理、远端关闭失败，以及系统 SFTP 备用路径。另有虚拟时钟测试验证持续传输超过 10 分钟不会被原来的总时限中断。

`compare_serial_and_parallel_many_file_uploads` 使用 200 个 8 KiB 文件，每次服务器写入模拟 10 ms 延迟，并逐文件校验内容。本机一次测量：单连接约 3.07 秒，4 连接约 0.72 秒。实际收益取决于链路延迟、带宽及服务器磁盘速度；测试报告耗时，不用速度倍数作为易波动的通过条件。
