# AI 对话面板布局分析与改版方案

日期：2026-09-12

范围：基于用户截图及当前源码进行界面分析和设计规划。本方案尚未实施，未修改运行时代码。未运行桌面应用，以下布局根因由截图与 CSS 层叠、组件分支共同确认，具体像素以实施后的浏览器测量为准。

## 1. 结论

建议采用“连续对话流 + 可折叠执行块”：普通 AI 回复以文字为主，命令和结果归入同一个工具块，模型错误使用紧凑通知。所有 AI 内容遵守相同的横向布局规则。

“大小统一”应解释为同类组件的宽度、边缘、内边距、标题行和控件尺寸统一；整体高度随内容变化。将一句问候和一段执行日志硬设为同高，会造成空白或内容截断。

项目的 PRODUCT.md 明确以终端为中心。当前工作区宽度范围为 360–560px，默认 420px，因此本次改版围绕侧栏工作流展开。保留历史、AI、脚本、SFTP 的工作区分工，以及现有终端与 AI 的协作关系。

## 2. 已确认的布局根因

### 2.1 成功和失败的可见边框不是同一层容器

- `frontend/src/domains/ai/presentation/styles/composer.css:281`：`.app-shell.theme-light .assistant-panel .message.ai.error` 将错误消息背景与边框颜色设为透明，其选择器优先级为 `(0,6,0)`。
- `frontend/src/domains/ai/presentation/styles/ai-cards.css:126`：恢复普通 AI 消息的可见边框，选择器优先级为 `(0,5,0)`，无法覆盖上述错误规则。
- `frontend/src/domains/ai/presentation/styles/ai-cards.css:35`：错误消息内部的通知又被设置为无边框、无背景、无内边距。

结果是成功回复显示完整消息外框，普通请求失败没有可见消息外框，而命令失败显示更里面的步骤外框。它们即使都声明 `width: 100%`，参照的父容器也不同。

### 2.2 状态切换还改变正文宽度

- `frontend/src/app/styles/workspace-polish.css:939`：普通 AI 消息使用 `padding: 10px 11px`。
- `frontend/src/domains/ai/presentation/styles/ai-final.css:57`：普通正文额外左缩进 28px。
- `frontend/src/domains/ai/presentation/styles/ai-cards.css:22` 与 `:30`：错误消息使用 10px 内边距，并取消正文左缩进。

按当前规则推导，若外层消息宽为 W，普通消息正文宽约为 W−52px，错误正文宽约为 W−22px。成功显示 W 宽的外框，失败步骤显示 W−22px 宽的内框，形成截图中的边缘不齐。

### 2.3 元信息占据了不合理的空间

`frontend/src/domains/ai/presentation/styles/ai-final.css:152` 将来源标签设为 `flex: 1 1 128px`，使“来源 · 本地终端”扩张为很长的胶囊。AI 头像、AI 名称、重复来源、失败徽章共同挤占首行。

建议每条回复只保留一个紧凑身份标识；生成来源采用短文本。顶部说明当前目标，历史消息继续保留来源信息供查看，避免切换终端后混淆。

### 2.4 长命令采用了两套相反的展示规则

`ai-final.css:283` 附近的错误建议会换行并限制为 88px 高；`frontend/src/shared/styles/typography.css:2` 的 Agent 命令则保持单行并强制横向滚动。截图因此同时出现短红框、长红框、横向滚动条和纵向滚动条。

命令预览应由同一个组件决定换行、收起、复制和展开规则。复制始终使用原始命令；视觉换行不得改变执行文本。

### 2.5 自动滚动缺少阅读位置判断

`frontend/src/domains/ai/presentation/components/AiPanel.vue:367` 直接滚到列表底部，`:616` 在文本长度或 streaming 状态变化时触发。流式回复期间回看历史可能被拉回底部。

## 3. 状态语义问题

| 当前表现 | 原因 | 目标行为 |
| --- | --- | --- |
| Shell 派发失败显示“请求失败” | `AiPanel.vue:831` 对所有 `message.error` 使用同一个标签 | 明确显示模型服务失败或命令执行问题 |
| 同一失败出现三次 | 步骤卡、消息徽章和 `AiErrorNotice` 同时渲染 | 错误详情与恢复动作只归属一个组件；任务摘要提供总体结果 |
| 尚未执行就展示“输出（无输出）” | `AgentStepCard.vue:54` 将所有 failed 都视为已执行 | 已知派发失败显示“命令未执行”，不生成空输出面板 |
| “Hello.”带“任务完成” | Agent 没有工具调用也进入 done | 零工具调用的普通回复不显示任务完成徽章 |
| 有步骤的任务没有整体结束提示 | `AiPanel.vue:843` 仅在没有步骤时显示终态 | 有执行步骤时提供一条任务摘要 |
| 非零退出码和“已完成”并列 | 步骤 completed 表示执行结束 | 区分执行结束、退出异常和任务完成，不改变 Agent 继续处理结果的能力 |

领域层已有 `errorKind: model | tool | protocol`，但 `useAgentSession.ts:293` 附近映射消息时未保留。实施时先保留错误来源，再补充必要的执行阶段或停止原因，使 UI 能区分未启动、执行中、已结束和结果未知。不能仅靠错误文本猜测执行是否成功。

截图中的“本地建议”需要兼容历史记录：当前新错误路径会清空建议命令，但旧消息的 command 仍可能被渲染。不能把历史展示能力误认为当前每次模型错误都生成兜底命令。

## 4. 参考方向与取舍

| 方向 | 适配程度 | 取舍 |
| --- | --- | --- |
| 连续对话流 + 执行块 | 推荐 | 回复易读，命令可核对，适合现有侧栏 |
| 全卡片任务列表 | 适合以后独立的任务历史页 | 可批量扫描，但在对话里边框和状态噪声偏多 |
| 对话、步骤、详情三栏 | 适合以后独立宽屏视图 | 360–560px 侧栏无法容纳，不作为首期布局 |

参考的是交互组织方式，具体尺寸、色彩和折叠策略为本项目设计建议：

- [VS Code Chat view](https://code.visualstudio.com/docs/agents/run/chat-view)：会话入口在上方，对话在中间，输入及会话配置在下方；侧栏可与主工作区并行使用。
- [Warp Terminal Blocks](https://docs.warp.dev/terminal/blocks)：把命令和输出组织为一个可独立操作的单元，适合本产品的执行结果呈现。

保持浅色、深色跟随应用主题。典型场景是开发和运维人员在办公桌前同时查看终端与 AI，长时间读日志并反复确认命令；采用中性色底、清晰文字和少量功能色。

## 5. 推荐布局

以下是结构线框，括号中的工具名称在实际 UI 中使用图标与 tooltip。当前工具没有提供原生图像生成能力，因此本轮以线框和尺寸规格表达视觉方向。

```text
历史       AI       脚本       SFTP
--------------------------------------
磁盘检查              (会话) (新建)
目标：本地终端          上下文 1.1k
--------------------------------------
                        查看本机磁盘

AI
我会读取本机磁盘的容量与剩余空间。

  [终端图标] 读取磁盘信息     未执行
  ----------------------------------
  命令预览                    (复制)
  终端尚未就绪，命令未执行。
  重试命令                  查看终端

AI
模型服务暂时不可用          HTTP 502
重试                (复制) (详情)

--------------------------------------
已选终端内容 12 行             (移除)
输入问题...
对话 | Agent       模型选择   (发送)
```

布局规则：

1. 顶部会话标题与操作合并为 44px 工具栏，目标与上下文保留一行约 28px；模型选择放到输入区，减少重复。
2. 中间只保留一个对话主滚动区。AI 回复、工具块和错误通知占用同一内容列，不因成功或失败改变左右边距。
3. 用户消息右对齐，最大宽度 85%；AI 正文左对齐，无整条绿色外框。普通问答不显示“任务完成”。
4. 工具块保留一个 1px 中性外框；命令、输出、失败说明是块内的平面分区，以分隔线区分，不继续套圆角卡片。
5. 输入区固定在底部，文字输入和工具栏占独立行。发送、停止切换使用同一个固定尺寸按钮，模式或标签换行不能遮住输入文字。

## 6. 尺寸与视觉规范

| 项目 | 建议规格 |
| --- | --- |
| 面板宽度 | 沿用 360–560px，默认 420px |
| 内容列 | 左右 16px；面板窄于 400px 时为 12px |
| AI 轮次间距 | 20px；同轮内容区间距 8–12px |
| 正文 | 14px，行高约 1.6，沿用现有中文无衬线字体 |
| 次要信息 | 12px；不再把大量关键内容缩到 10–11px |
| 命令和输出 | 12–13px，沿用现有等宽字体 |
| 工具块 | 8px 圆角，1px 边框，12px 内边距 |
| 工具摘要行 | 最小高度 36px；允许长标题换行，状态占稳定列 |
| 图标按钮 | 32×32px，焦点轮廓清晰；触屏布局使用更大点击区 |
| 输入框 | 起始两行，自动增高，约六行后内部滚动 |
| 色彩 | 白色或中性深灰表面，深色正文；绿色主操作、红色错误、琥珀色待确认 |

主题变量只控制颜色和表面，不控制宽度、内边距和 DOM 层级。错误通过图标、明确文案和小面积色彩呈现；不让头像、外框、内框、徽章全部同时变红。

消息没有统一固定高度。工具摘要采用统一最小高度，正文自然增高；只对长日志详情设置滚动上限。

## 7. 交互与状态规则

| 状态 | 默认内容 | 操作 |
| --- | --- | --- |
| 正常回复 | 可选中文本和 Markdown | 复制；更多菜单容纳次要动作 |
| 正在生成 | 当前阶段与已等待时间，不显示虚构百分比 | 输入区停止按钮 |
| 待执行 | 执行目标、完整可审阅命令、必要风险信息 | 执行、跳过；沿用现有风险审批 |
| 执行中 | 当前步骤与最新输出 | 停止；超时后使用现有等待或停止决策 |
| 执行结束 | 摘要、退出码、耗时；完成任务后可折叠旧步骤 | 展开输出、复制、定位终端 |
| 未成功派发 | “终端未就绪，命令未执行”及原因 | 重试命令、查看终端；不展示空输出 |
| 执行异常 | 保留真实输出与退出码 | 按现有执行策略重试或继续处理 |
| 模型 502/503 | 一条服务失败通知，保留已有部分回复 | 重试请求；模型选择仍可访问，详情折叠 |
| 停止或结果未知 | 明确停止原因或“结果未确认” | 查看终端；不宣称命令成功或失败 |

补充规则：

- 模型请求重试沿用原问题和现有消息替换行为；命令重试沿用现有执行目标检查与审批。两个操作不得混淆。
- 长命令默认提供统一预览，保留完整原文复制与展开能力。待审批的命令不能仅靠被截断的预览让用户确认执行。
- 默认预览不产生多重纵向滚动。详细输出展开后可有一个日志滚动区；表格类终端输出保留格式，超宽时在日志区域横向滚动。
- 任务结束后成功步骤可收起为摘要；正在阅读或手动展开的步骤不因状态更新突然收起。失败步骤默认保留错误原因。
- 已执行但没有文本输出时用一行说明，并在有依据时显示退出码；派发失败不等同于“已执行但无输出”。
- 来源标签不伸展填满一整行。当前目标改变后，历史消息仍可以查看原来源，执行前显示真实目标。
- 用户在底部附近时跟随流式输出；上滚后保持阅读位置，提供“回到最新”图标。发出新问题时主动定位新轮次。
- 普通复制等图标可在 hover 或键盘聚焦时显示，但必须预留位置。重试、审批、停止等关键操作始终可见。
- 首期保留现有 Ctrl/Cmd+Enter 发送、Enter 换行及中文输入法处理，避免把交互习惯变更混入视觉重构。
- 空会话保留可直接输入的界面；没有配置时显示配置入口。展开详情使用 aria-expanded，错误和进度按语义播报，避免历史错误重复抢占读屏。

## 8. 实施顺序

### P0：先修复当前不一致

统一外层消息结构与正文边距；移除相互覆盖的透明外框规则；收回来源标签的伸展；使用明确错误类型替换固定“请求失败”标签；已知未执行时去掉空输出区。

阶段验收：同宽面板内，同级 AI 内容左右边缘一致，所有状态切换不改变横向几何；同一错误原因及恢复动作只出现一次。

### P1：完成对话面板改版

采用无外框 AI 正文、统一执行块和紧凑服务错误；整理头部与输入区；补齐折叠、滚动跟随、复制和焦点状态；两种主题使用同一结构。

组件建议沿用现有实现边界：从 `AiPanel.vue` 提取一个消息项负责共同布局；让 `AgentStepCard.vue`、`AiErrorNotice.vue`、`AiMarkdownMessage.vue` 负责各自内容；仅在三者的代码展示确有复用时提取命令预览组件。无需替换 Vue 或 Agent 循环。

### P2：收敛样式并验证

将 AI 布局的重复定义从 `workspace-polish.css`、`assistant.css`、`ai-final.css`、`composer.css`、`ai-cards.css` 收敛到有明确归属的规则。对共享脚本输入区的选择器逐项核对，避免影响脚本工作区。

主题文件只保留 token 或颜色差异；停止增加新的 final/polish 文件和更高优先级选择器。旧记录的错误类型缺失时提供兼容呈现，新消息持久化结构化分类。

## 9. 验收矩阵

- 宽度：360、420、430、554、560px；同时验证大窗口里的窄侧栏，使用容器尺寸判断响应式布局。
- 主题与缩放：浅色、深色、100% 与 125% 缩放；检查正文对比度和字体回退。
- 内容：一句话、中英文长回复、长路径、长命令、多行命令、大量输出和真实终端表格。
- 状态：生成、审批、执行、成功、非零退出码、派发失败、502/503、部分回复中断、超时、停止与历史消息恢复。
- 布局：同级内容边缘误差不超过 1 CSS px，正文没有面板级横向溢出；允许日志区域有必要的横向滚动。
- 操作：重试行为和目标正确，复制得到完整原文，菜单不被滚动容器裁剪，按钮不遮住正文或输入区。
- 阅读：流式输出不打断上滚阅读，展开日志保持当前位置，操作图标出现时不改变行高。
- 回归：脚本输入区与终端审批流程保持可用；运行项目现有 AI、工作区和 UI 相关检查，并补充真正覆盖状态差异的呈现测试及浏览器截图。

本轮交付为方案。后续实现应先通过 P0 的几何和状态验收，再推进完整视觉改版。
