**Windows 界面优化方案**

日期：2026-10-27。状态：第 1、2 阶段已实现并通过前端验证；第 3 阶段待实施，真实 Windows WebView2 观感待复核。

依据：用户提供的 Windows 浅色主题截图、当前前端源码和 [PRODUCT.md](../PRODUCT.md)。截图中的字体观感尚未通过 Windows 运行时验证；下列尺寸和颜色为实施目标，最终以同环境对照验收。

**1. 优化目标与范围**

保留以终端为中心的工作区，让中文、命令和关键状态更易读，同时减少 AI 侧栏中的重复边框、元信息和留白。优先级为：文字可读性 → 待确认状态 → 步骤卡片密度 → 标签与窄窗口适配。

字体适配作用于 Windows；卡片组织、状态表达和标签空间调整作为共用界面改进，覆盖浅色、深色主题。终端字号继续服从用户设置，审批按钮继续沿用现有授权和风险处理规则。

**2. 优化前基线与已确认原因**

| 项目 | 当前实现 | 处理依据 |
| --- | --- | --- |
| Windows 字体 | `main.ts` 已加载 Noto Sans SC Variable 和 JetBrains Mono；CSS、xterm 各有独立的字体栈 | 先检查实际渲染字体和字体资源加载，避免重复添加字体依赖 |
| 字号 | 基础字号从 11、12、13px 开始；终端默认 13px，Windows 行高 1.18 | 提升关键中文与正文的阅读尺寸，保留紧凑工具栏 |
| 固定命令栏 | Agent 接管时父容器透明度 `.7`，禁用按钮透明度 `.45` | 两层叠加后有效透明度约 `.315`，改为显式禁用颜色 |
| 待确认输入框 | 同时存在 `is-running` 和 `is-awaiting-decision`；后者暂停彩色边框动画，但保留彩色描边 | 等待状态改用静态、统一的待确认样式 |
| 步骤卡片 | 成功步骤已默认折叠，但摘要仍包含标题、状态、自动执行、退出码和耗时 | 优化现有摘要，保留展开后的完整记录 |
| 顶部标签 | 标签最大宽度为 232px | 放宽长名称的显示空间，同时保留多标签滚动 |
| 辅助侧栏 | 当前默认/常规最小宽度 320px，最大 560px；空间受限时由布局函数进一步约束 | 以当前源码为准，320px 必须纳入验收；早期文档中的默认 420px 已过时 |

**3. 第一阶段：字体、字号与可读性（P1）**

先记录截图对应版本、Windows 显示缩放、WebView2 版本、页面实际 CSS 视口和 `devicePixelRatio`，建立修改前样本。

分别检查界面文字与终端文字：界面检查 `data-platform="windows"`、字体请求和实际渲染字体；终端检查 `terminal.options.fontFamily`、字号及字体就绪后的网格测量。仅看到计算样式中的字体族名称，不能证明每个字形都使用了该字体。现有字体就绪后尺寸同步逻辑应继续复用，确认中文、光标和选区对齐。

| 使用位置 | 目标规格（CSS 像素） | 适用方式 |
| --- | --- | --- |
| 会话标签、工具栏、表单文字 | 13px，常规字重 400，选中项 600 | 保持现有紧凑布局；逐项调整偏小的中文标签 |
| AI 阅读正文、步骤标题 | 14px，行高约 22px；步骤标题字重 500 | 正文层级清晰，长标题允许完整换行 |
| 状态、说明、接管提示 | 12px，行高 18px | 中文辅助文字的最低目标；纯数字序号可维持现有尺寸 |
| AI 命令与输出 | 13px，行高约 20px | 继续使用等宽字体及现有完整预览能力 |
| Windows 终端初始值 | 14px，行高 1.25 | 用于新安装或用户主动恢复默认；已有保存字号继续生效 |
| 图标与按钮 | 常用图标 14–16px；常用按钮高 32px | 小型内联操作可保留 28px；按光学对齐统一图标基线 |

字号调整按组件角色落地。保留全局 `--font-xs` 给适合的小型数字标记，把关键中文从 10–11px 调整到 12px，避免一次放大全部控件导致设置页和工具栏溢出。

Windows 界面字体继续使用已打包的 Noto Sans SC Variable，并保留 Segoe UI、Microsoft YaHei UI 系统兜底。终端保留现有 Cascadia、JetBrains Mono、Consolas 与中文兜底链；字体顺序如需变化，应以实机对照为依据。调整终端默认值时同步处理新设置和无设置回退路径。

浅色主题的文字与表面目标如下，实施时归入已有语义变量，并核对最终计算颜色：

| 角色 | 建议值 | 使用位置 |
| --- | --- | --- |
| 主文字 | `#1f2937` | 标题、正文、可执行操作 |
| 辅助文字 | `#5f6b7a` | 耗时、连接信息、说明 |
| 禁用文字 | `#7b8794` | 暂不可用的按钮和选择项 |
| 主表面 | `#ffffff` | 阅读区、终端及终端边距 |
| 次级表面 | `#f5f7f9` | 工具栏、代码标题区等小面积分区 |
| 分隔线 | `#dce2e8` | 面板边界与必要的内容分隔 |

固定命令栏恢复父容器不透明，由禁用按钮自己的文字和背景颜色表达状态。禁用语义继续由 `disabled` 控制。该规则限定于相关区域，避免改变所有按钮的表现。

深色主题采用对应的文字、辅助文字和禁用颜色，使用同样的角色划分。终端画布、外层边距和固定命令栏继续使用一致背景，延续现有终端背景约定。

阶段验收：关键中文达到目标字号；固定命令在禁用时仍能辨读；中英文混排、光标、选区对齐；已有终端字号设置在升级后保持原值。

**4. 第二阶段：统一状态与收紧步骤卡片（P1/P2）**

用已有运行状态派生展示状态，优先识别保存授权、待审批和等待超时处理。待确认的卡片样式依据 `awaitingApproval` / `awaitingTimeout`，底部状态依据当前待处理对象；历史记录中的 `pending` 本身不代表当前正在请求用户操作。

| 状态 | 卡片表现 | 输入区与底部状态 |
| --- | --- | --- |
| 空闲 | 历史步骤保持正常摘要 | 中性边框，获得焦点时使用绿色轮廓 |
| 规划、分析、回复、执行 | 当前步骤按真实阶段显示文字；执行中使用轻量旋转图标 | 绿色状态标记；输入框采用稳定边框 |
| 等待确认命令 | 琥珀色“等待确认”标识与浅色标题背景，完整展开目标、风险、命令和操作 | 同色静态状态；“查看”继续定位当前待确认步骤 |
| 等待超时处理 | 琥珀色“等待超时处理”，展示已有部分输出和处理按钮 | 静态等待状态，文案明确等待对象 |
| 正在保存授权 | 明确显示“正在保存授权”，操作按钮保持禁用 | 轻量忙碌指示，与等待确认区分 |
| 正常结束 | 中性卡片、绿色完成标记 | 结束后回到普通输入状态 |
| 执行异常、结果未知 | 使用现有异常语义与对应文案，保留恢复操作 | 错误详情集中于对应步骤 |
| 停止任务、停止等待 | 沿用真实生命周期状态 | 明确区分停止等待与命令执行结果 |

移除输入框多色流动描边，将动态反馈集中到状态图标。浅色等待状态可使用文字 `#8a5a12`、背景 `#fff5df`、边框 `#e5c58b`；深色使用独立配色。风险类别继续保留其专属标识，普通等待状态使用琥珀色。所有状态均同时提供文字或图标。

步骤卡片按以下结构调整：

1. **已完成、已跳过的摘要**：显示标题、状态和耗时；`exit 0`、自动执行依据与完整目标信息放入展开内容。非零退出、结果未知及未执行原因继续显著展示。
2. **摘要尺寸**：内边距约 8px 12px，标题与状态间距 4px；单行标题的完整摘要目标约 60px 高。长标题随内容增长，保持完整可读。相邻步骤间距 6–8px。
3. **当前待处理步骤**：保持完整展开，标题下紧接执行目标与风险摘要；命令区沿用现有代码组件。操作区用一条分隔线建立层级，减少其他内部横线。
4. **按钮层级**：现有“查看风险”或“仅执行本次”作为主操作；授权、跳过、停止保持清晰的次级层级。授权能力、可用性与事件绑定沿用当前逻辑。
5. **思考过程**：保持独立折叠入口，减少上下空白，辅助色文字仍清晰可读。用户手动展开的阅读状态继续保留。
6. **命令内容**：视觉排版与原始文本分离，复制和执行始终使用原始命令；长命令保留横向查看和完整预览入口。

目标效果示例：一个已完成步骤只需读到“检查配置 · 已完成 · 162ms”；当前待确认步骤直接呈现“等待确认 → 执行目标 → 风险与命令 → 可用操作”。

阶段验收：同一待确认步骤的卡片和底部状态语义一致；成功摘要更紧凑；风险、执行目标和原始命令完整可查；状态变化和折叠不会强制打断用户回看历史。

**5. 第三阶段：标签、区域层级与窄窗口（P2）**

会话标签按内容自然宽度布局，将单标签宽度上限由 232px 调整为约 320px，常规最小宽度保持 108px。少量连接获得更完整的名称空间，多连接继续使用现有横向滚动、选中项定位和全部终端列表。添加、同步输入等操作保留独立区域。

选中标签使用统一的浅绿色背景、清晰文字与底部标记。接管标识和关闭按钮保留稳定占位，截断集中发生在名称区域，完整名称通过现有提示或连接列表可查看。

保留“会话标签 → 终端/文件视图 → 工具内容”的现有导航层级。工具栏可用轻微中性底色与阅读区区分；终端背景继续一致。AI 卡片维持单一外框，圆角以 6–8px 为主，输入框可保留 10px，减少内部框套框。

| 辅助面板宽度 | 目标布局 |
| --- | --- |
| 420–560px | 左右内容边距 16px，操作区优先同一行排列 |
| 320–399px | 左右边距 12px，状态元信息和操作按钮按内容换行，保持文字字号 |
| 受到主布局进一步约束 | 保留 `min-width: 0` 与内容折行；面板外层保持无横向溢出，代码内容可独立滚动 |

输入区的配置选择、上下文、设置和发送/停止按钮在窄栏允许分行排列。发送/停止按钮始终可见，菜单可正常溢出输入框容器；文字和操作区各占自己的布局空间。

阶段验收：宽屏长连接名称获得更多空间；20 个标签时当前项和右侧操作均可达；320px 侧栏无内容遮挡、按钮覆盖或外层横向滚动。

完成标准：

- 关键中文说明至少 12px，正文、代码及终端达到选定阅读规格，无裁切、错位、缺字；字形变化使用同系统、同缩放、同内容截图比较。
- 作为本项目的视觉验收目标，正文和说明文字与实际背景的对比度至少 4.5:1，禁用文字至少 3:1；使用最终合成颜色计算，包含透明度影响。
- 待审批卡片明确显示等待状态、执行目标、风险、命令和可用操作；审批规则与真实执行行为通过现有测试验证。
- 320px 面板下输入文字、操作按钮和配置菜单可达；长命令、长输出只在其内容区域滚动；外层面板无横向溢出。
- 成功步骤压缩的是元信息和间距，完整标题、命令、目标和退出信息仍可查看。
- 终端字体加载或字号变化后，网格、光标和选区重新对齐；窗口和面板调整不引入持续尺寸震荡。
- 系统“减少动态效果”开启时停止非必要动画，键盘焦点始终可辨。

**8. 第 1、2 阶段实施记录**

- 步骤卡片标题保持完整换行，减少内边距和重复分隔；执行目标允许完整换行，审批与恢复按钮继续使用原有事件与权限判断。
