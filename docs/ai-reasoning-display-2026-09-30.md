# 思考与正文分离分析

## 原因

- Agent 已分别保存每轮的 `reasoning` 和 `text`，但展示函数将两者拼成一段 Markdown。因此模型推理、工具前说明显示在一起。
- 普通对话只读取正文增量，没有主动拼接推理，但也没有转发、接收和持久化独立推理字段。只返回推理而缺少正文的 JSON 响应，还可能落入原始 JSON 正文兜底。

## 修改后的行为

- Agent：每轮独立推理 → 普通说明 → 工具卡片，保持原有事件顺序；最终正文独立展示。
- 普通对话：独立推理与回复正文分别保存、渲染。
- 思考默认折叠，用户可以手动展开；流式更新和任务结束不覆盖手动展开状态，重新打开会话时默认折叠。
- 思考展开后复用正文 Markdown 渲染器，但不提供执行命令按钮；折叠时不创建 Markdown 子树。
- 停止、错误和正常完成均保留已收到的独立思考，思考不加入后续对话正文或命令提取。
- 普通对话和 Agent 共用兼容接口的推理字段提取规则；仅有推理的响应不会作为 JSON 正文展示。

## 历史记录与识别边界

已有 `agentTimeline` 的记录可以利用独立字段直接恢复分离。更早只保存合并思考文字的记录无法可靠还原正文边界，作为“历史思考记录”整体折叠。普通对话过去丢弃的推理字段无法追溯恢复。

分离以接口提供的独立字段为准；不凭措辞猜测正文中的哪一句属于思考，也不把正常回复中的分析段落自动隐藏。

## 验证

前端运行时测试覆盖两种内容同时到达、多轮工具、停止/错误时未刷新的增量、持久化恢复、重试清理及正文命令提取。后端测试覆盖混合 SSE 帧、兼容推理字段、用量和仅推理响应。浏览器验证两种模式默认折叠、正文可见、展开 Markdown、完成后保持手动状态及重新加载后的折叠恢复。
