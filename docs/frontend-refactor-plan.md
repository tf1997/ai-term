# 前端渐进式重构方案与进度

更新时间：2026-09-08

开发分支：`refactor/frontend-foundation`（从 `main` 新建，已有未提交的本轮改动一并保留）。

## 1. 目标与边界

在保持现有中文界面、终端优先布局和业务行为的前提下，逐步降低前端模块的耦合，建立可测试的状态与副作用边界。本轮是结构重构，不是视觉改版。

- 保留 Vue 3、TypeScript、Vite、Tauri 和现有依赖，不引入新的状态管理或 UI 框架。
- 不修改 Rust 后端、IPC 协议、终端执行、Agent 审批规则或敏感命令处理。
- 保留本地存储键、平台字体默认值和既有迁移，避免用户配置丢失。
- 每次只移动一个明确的职责，接线、测试、文档一起更新，不先搭建大量空目录。
- 所有后续开发在上述重构分支进行；未经要求不提交、不推送。

## 2. 基线与优先级

重构前：

| 模块 | 现状 | 首要问题 |
| --- | --- | --- |
| `AppShell.vue` | 2,750 行 | 设置、主题、终端会话、工作区数据和全局交互集中在一个组件 |
| `SettingsSidebar.vue` | 429 行 | 与应用壳重复定义设置类型、默认值和预算校验 |
| `styles.css` | 14,623 行 | 全局规则及多轮覆盖混合，直接按名称拆分会改变级联顺序 |
| 终端、传输、脚本、AI 面板 | 各约 70–121 KB | 渲染、异步任务、状态和资源清理混合 |
| `production-ui-check.mjs` | 主要检查源码字符串 | 绑定具体实现位置，需要逐步增加行为测试，而不是删掉契约 |

初始生产构建通过；存在既有的 Vite CJS 与大于 500 KB 的 chunk 警告。初始脚本测试在 Agent 循环套件未能结束；限时复核发现该未修改套件存在断言失败和超时，不能将全量测试视为全绿基线。

## 3. 目标职责划分

| 位置 | 职责 |
| --- | --- |
| `src/types/` | 跨组件共享的数据契约，不复制业务类型 |
| `src/lib/` | 可独立测试的规则、格式转换及明确的外部适配边界 |
| `src/composables/` | Vue 状态、派生值、watch 与生命周期资源清理 |
| `src/components/` | 视图、表单草稿、props/emits 和必要的页面组合 |
| `src/styles/`（后续） | 在保持级联顺序的前提下划分基础、布局、组件和主题样式 |

纯规则模块不读取浏览器全局对象；存储适配器允许注入测试替身；composable 在自己的生命周期中释放自己注册的资源。应用壳保留跨功能编排和用户提示，不再重复实现子模块规则。

### P3 全量面板拆分顺序

1. `TerminalPane.vue`：终端实例/连接生命周期、输入状态、输出捕获、快捷命令和工具栏；真实终端与浏览器预览分别验收。
2. `AiPanel.vue`：聊天请求/流式取消、Agent 任务编排、会话展示和输入区；不改变 Agent 审批或命令执行策略。
3. `FileTransferPanel.vue`：目录浏览/选择、传输队列、路径规则、上传下载及对话框；保护连接代次和异步结果隔离。
4. `ScriptPanel.vue`：脚本库/编辑草稿、生成请求、执行编排和结果展示；保护执行目标、风险确认和中断行为。
5. 其余界面与辅助模块：逐一检查设置、连接、历史、Agent 步骤、Markdown、Tauri 适配及 Shell/Agent 工具；按职责处理混合模块，不为凑行数机械分片。

## 5. 验证与回归规则

在 `frontend/` 下运行：

- `npm run test:settings`：P1 快速行为回归。
- `npm run test:workspace`：P2.1 工作区尺寸、输入事件和资源清理回归。
- `npm run test:overlays`：P2.2 通知去重/计时器、菜单定位/关闭和卸载清理回归。
- `npm run test:tabs`：P2.3 终端标签、同步目标、滚动测量、指针拖动及卸载回归。
- `npm run test:workspace-data`：P2.4 连接历史、会话元数据、消息缓存与持久化队列回归。
- `npm run test:workspace-browser`：生产预览下的终端标签与全局 AI 草稿会话交互；准备要求见第 12 节。
- `npm run test:ui`：界面接线、可访问性和安全相关源码契约。
- `npm run build`：Vue/TypeScript 检查与生产打包。
- `npm run test:scripts`：完整脚本套件，包含新增测试；注意上述既有 Agent 套件问题，必要时使用限时命令单独复核。
- `git diff --check`：补丁空白检查。

UI 契约只迁移到真实的职责所有者，不拼接所有源码来绕过断言；逻辑行为优先由执行测试保护。

浏览器验证至少包括：初始主题、鼠标/键盘切换、刷新后恢复、设置保存/重载，以及存储失败后当前会话仍可操作。Tauri 真实终端与远程连接必须与浏览器预览区分记录，未执行的验证不标记通过。

## 6. P1 兼容性说明

- 默认字号仍是 13，允许 11–22；Agent 步数 1–25，默认 25；命令超时 15–600 秒，默认 120 秒。
- 托管默认字体只在加载时按平台迁移，不因表单校验覆盖用户当次主动选择的字体。
- Windows 旧版 15px 校正只执行一次；校正写入失败不误记成功，也不丢弃其他有效偏好。
- 设置存储失败显示“已应用，但未保存”，不再错误地提示已保存。
- 不修改应用模板布局、全局样式和业务面板协议；完成 P1 时：应用壳 2,750 → 2,607 行，设置面板 429 → 397 行。
