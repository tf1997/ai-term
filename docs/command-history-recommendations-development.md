# 历史命令与命令推荐改造开发文档

## 1. 背景

AI Term 当前存在三套命令复用入口：

- 历史命令面板：搜索、复制、预览并直接再次执行。
- 终端输入补全：混合本次终端、连接历史和系统候选。
- 快速命令栏：保存固定命令，并在点击后填入终端。

三套入口的执行语义和数据来源不一致。历史命令会直接执行，快速命令和补全只填入；历史推荐位于快速命令设置弹窗内，本地统计又在计数前去重，无法识别真正高频命令。命令时间以本地化字符串保存，但 SQLite 按文本排序，可能造成最近记录乱序和淘汰错误。

本次改造将命令复用统一为“发现 -> 核对 -> 填入 -> 用户确认执行”的可审查链路。

## 2. 目标

### 2.1 用户体验目标

- 历史命令默认只填入当前活动终端，不自动发送回车。
- 历史面板提供“最近”和“常用”两种明确视图。
- 历史命令可以一键固定到当前连接的固定命令栏。
- 固定命令优先进入终端输入补全。
- 推荐结果由本地历史确定性计算，不依赖网络或 AI Provider。
- 复制、固定、填入失败均有明确反馈，长命令操作不再依赖双击。

### 2.2 数据正确性目标

- 新历史记录统一保存为 ISO 8601 UTC 时间。
- SQLite 对 ISO、SQLite 时间和旧本地化时间采用兼容排序，保证新记录不会被旧格式记录错误淘汰。
- 推荐先统计原始事件，再去重和排序。
- 大小写敏感的完整命令不被错误合并。
- 明显包含密钥、Token 或内联密码的命令不进入历史和推荐。

## 3. 非目标

以下能力需要 Shell integration 或更大的存储模型调整，不在本阶段实现：

- 采集 `cwd`、退出码、耗时和真实 PTY 会话结果。
- 跨连接全局历史搜索、游标分页和 SQLite FTS。
- 将固定命令状态提升为全局 Vue store。
- AI 将多条历史命令提炼为带参数的模板。
- 自动执行推荐命令。

## 4. 交互设计

### 4.1 历史面板

面板包含两个视图：

- `最近`：按兼容时间顺序展示最近 100 条已加载记录。ISO 时间精确排序，无法解析的旧 locale 时间按近似插入顺序排列。
- `常用`：按完整命令聚合，展示执行次数和最近出现位置。

搜索作用于当前视图。历史行提供以下动作：

1. 预览：仅长命令显示，打开完整命令预览。
2. 复制：复制命令并显示成功或失败状态。
3. 固定：加入当前连接的固定命令栏。
4. 填入：将命令写入当前活动终端，但不追加回车。

整行不响应双击，避免双击操作按钮造成重复写入或意外打开预览。预览弹窗的主操作同样为“填入终端”。

### 4.2 固定命令

固定命令继续按连接保存在现有 `localStorage` key 中，保持升级兼容。新增统一提交函数负责：

- 安全校验和长度校验。
- 精确去重。
- 12 条上限检查，不静默挤掉已有命令。
- 更新当前终端状态、持久化并广播现有变更事件。

历史面板只发出固定意图，实际写入仍由当前活动 `TerminalPane` 完成，避免产生第二套状态源。

### 4.3 输入补全

候选优先级为：

1. 当前连接的固定命令，保持用户定义顺序。
2. 当前标签挂载期间观察到的命令和当前连接历史，按频次与最近位置排序。
3. 与当前 Shell 匹配的系统候选。

补全仅在输入长度不少于 2 个字符、光标位于行尾、输入状态可靠且当前处于 Shell 提示符时出现。`Tab` 继续交给 Shell 自己的补全。

完整命令使用精确字符串作为聚合 key；搜索仍可忽略大小写。这样不会把 Linux 上仅路径大小写不同的命令合并。

补全中的“当前”只表示当前 `TerminalPane` 组件挂载期间观察到的输入，不代表真实 PTY session。持久化的 `terminal_id` 仅用于标签来源追踪，不能作为 Shell session 标识；真实 session 元数据仍属于后续 Shell integration 范围。

### 4.4 本地常用推荐

本地推荐直接基于最近 80 个未去重、非敏感历史事件统计：

- 使用次数使用 `log1p(count)` 降低陈旧高频命令的垄断效应。
- 最近出现位置使用 `exp(-age / max(1, eventCount / 4))` 提供衰减加分。
- 高风险和敏感命令直接排除。
- 同分时依次按次数、最近位置和命令文本稳定排序。
- 历史候选不足时追加内置默认命令，再做精确去重并截取前 12 条。
- 固定命令推荐流程不调用 AI Provider，也不发送命令历史或终端快照。

AI 对话和 AI 风险分析仍是独立的显式联网功能，会按原有上下文策略发送终端快照和最近命令；发送前会再次排除敏感命令。该行为不属于固定命令推荐链路。

## 5. 事件与组件契约

### 5.1 历史填入

```text
CommandHistoryPanel.fill
  -> WorkspacePanel.fillCommand
  -> AppShell.fillHistoryCommandOnActiveTerminal
  -> active TerminalPane.fillCommand
```

该链路只操作当前活动终端，不使用多终端执行目标，也不调用 `executeCommandOnTerminalIds`。
`TerminalPane.fillCommand` 会更新当前终端的输入追踪并写入文本，但关闭 `terminalInput` 同步事件，因此即使用户选择了多个终端目标也不会广播。写入内容不包含 `\r` 或 `\n`。

### 5.2 固定命令

```text
CommandHistoryPanel.pin
  -> WorkspacePanel.pinQuickCommand
  -> AppShell.pinQuickCommandOnActiveTerminal
  -> active TerminalPane.pinQuickCommand
  -> localStorage + ai-term:quick-commands-changed
```

同一连接的其他终端通过既有变更事件同步，不同连接继续隔离。

### 5.3 现有历史作用域

- `connection_id` 是查询、前端缓存和 1000 条淘汰策略的权威范围。
- `workspace_session_id` 当前统一写为 `connection-history`，命令历史不随 AI workspace 切换。
- 删除 AI workspace 只删除对应 AI 消息，不删除命令历史。
- `terminal_id` 仅保存 UI 标签来源，不代表真实 PTY session，也不参与查询范围。

## 6. 时间兼容方案

新记录使用应用现有的 `nowText()`，保存 ISO 8601 UTC 字符串。数据库不做不可逆的旧时间文本迁移，因为历史版本可能产生任意系统 locale 格式。

SQLite 查询使用兼容排序键：

```sql
COALESCE(julianday(created_at), 0.0), rowid, id
```

- ISO 8601 和 SQLite `CURRENT_TIMESTAMP` 可按真实时间排序。
- 无法解析的旧 locale 记录降为旧数据，并以 `rowid` 和 `id` 保留大致插入顺序。
- 最近 300 条查询的内外层使用同一排序键。
- 每连接保留 1000 条的淘汰逻辑使用同一排序键。

后续在引入 `cwd/outcome/source` 等执行元数据时，再一次性增加 canonical epoch 字段和索引。

## 7. 隐私规则

以下内容视为敏感命令，不写入历史、不参与固定推荐：

- 常见 `--password`、`--token`、`--api-key`、`--secret` 参数及其值。
- `Authorization: Bearer/Basic` Header。
- 常见密钥环境变量赋值。
- URL 中的内联用户名和密码。
- 私钥正文标记。

该规则只控制记录与推荐，不阻止用户在终端执行命令。

敏感检查在两个前端边界执行：`TerminalPane.recordCommand` 阻止事件产生，`AppShell.recordCommand` 在写入缓存和 SQLite 前再次校验。Rust 存储层为兼容旧客户端和既有数据，不迁移或删除历史行，也不把该正则作为数据库约束。

旧版本已经写入的敏感记录仍可在历史面板中显式查看，但会在输入补全、固定命令推荐和 AI Provider 上下文组装时再次过滤；尝试将其固定时也会被拒绝。此策略避免静默删除用户数据，同时阻止旧凭证继续进入自动推荐或联网上下文。

## 8. 可访问性与状态

- `最近/常用` 使用 `tablist/tab/tabpanel` 语义。
- 视图标签使用 roving `tabindex`，支持 Left/Right/Home/End 键切换。
- 复制反馈使用 `role="status"` 和 `aria-live="polite"`。
- 所有图标按钮提供中文 `title` 和 `aria-label`。
- 预览支持 Escape 关闭、Tab 焦点圈定，并在关闭后恢复仍存在的触发按钮焦点。
- 动画只表达 hover、focus 和选择状态；减少动态偏好下关闭非必要过渡。

## 9. 验收标准

- 从历史面板填入命令后，终端收到命令文本但没有 `\r`。
- 命令行已有内容或 Shell 未就绪时拒绝填入，并显示明确 toast。
- 重复固定幂等，高风险、敏感、过长或第 13 条固定命令被拒绝。
- 固定命令立即出现在同连接终端的固定命令栏和补全首位。
- `cat README.md` 与 `cat readme.md` 保持为两个候选。
- 常用视图聚合已加载的最多 300 条记录，展示前 50 个命令；重复命令次数和最近位置参与排序。
- 含旧 locale 时间和新 ISO 时间的数据仍能保证新记录位于最近集合，并正确执行保留策略。
- 历史复制有反馈，双击任意历史操作不会执行两次。
- 前端类型检查、生产 UI 契约、Rust 单元测试和构建全部通过。

## 11. 后续阶段

第二阶段引入 Shell integration，优先使用 OSC 7/633 或各 Shell hook 采集 `cwd`、退出码、耗时、Shell 类型和真实 terminal session。推荐排序再加入同目录、成功率和时间衰减，并将聚合与分页查询下沉到 Rust。

第三阶段提供显式选择命令后的“AI 提炼为模板”。发送前展示 Provider、命令清单和脱敏结果，AI 只生成可编辑模板，不自动固定或执行。
