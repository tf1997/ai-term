## 本轮发现与处理

1. **M8 用户回复没有直接接续原计划，已补齐。** `ask_user` 能保存等待状态，但主输入框的回复曾调用 `beginAgentTask` 新建运行。已新增原生 `reply_agent_run`：同一运行获取新所有权，保留原目标、计划、问题/回复与历史事实；等待结束后撤销历史验证的当前有效性。错目标、序号过期和重复提交拒绝；换终端会话或存在未知效果先走恢复核对。普通输入框、消息内及已保存任务入口均接入，旧问题与新回复分别展示。完整回归通过；浏览器验证连续两次提问回复及重新打开后保留同一运行和计划版本。
2. **取消、跳过计划项被永久计为未完成，已修复。** 现在从剩余安排中移出，并单列数量与历史状态；只有真实完成项计入“已完成”。必要验证仍须有实际证据，取消安排不能免除缺失或失败的必要检查。原生未完成查询与恢复入口同步；已派发而结果未知的命令或文件操作仍需核对，不能因取消计划或模型结束而隐藏。计划的七种状态、未知命令及重启后的查询/恢复已覆盖；原生检查点 14/14、前端计划/检查点定向 24/24、实际计划调整 UI 流程通过。
3. **M10 保存后的待整理来源已补齐。** 草稿和 SQLite 记录逐项保存未选中、异环境、失败/未知、不支持工具及缺少可靠文件证据的步骤 ID、工具、状态与原因；没有选入的验证项单独保留必要性、原证据引用和历史状态，不复制原命令、文件正文、验证目的/预期或批准。重新打开后可查看全部来源，最多 1,000 个步骤，不截断引用；元数据上限 512 KiB，实际脚本仍为 64 KiB，超限明确拒绝。浏览器验证手动遗漏、独立 SSH、元数据恢复、异环境及必要健康检查；原生保存/重开和拒绝伪造字段均通过。静态 Zsh 的 `print` 曾在导出 Bash 中以 127 失败，现调用 Zsh 子进程并通过位置参数传参；本机真实执行验证成功、特殊字符保持数据及失败停止。依赖交互会话状态的命令仍逐项标记待整理，原生策略对 Zsh 内层保留未知并要求重新审核。
4. **M5 补齐 macOS 本地覆盖。** 用户回复“本机是macos 本地终端可验证”。本机 Zsh 5.9、Bash 3.2 回退、Bash 5.2.37、实际流重放以及原生文件读改恢复/冲突已复验。此前 Linux/Bash 直连、SFTP 开/关、原生 exec 和真实模型文件工具已有实测。Windows 客户端、远端 macOS SSH 等没有实测证据的矩阵仍单列；本地验证不替代它们。
5. **M8 摘要及确认依据已补齐。** 普通与恢复摘要复用同一个紧凑结构，保留各项状态、关键执行步骤引用、计划调整原因和用户确认依据。描述/预期过长时只缩短文字；极端引用本身仍超出 18,000/19,000 字符预算时，明确停止模型请求并保留完整记录，不发送缺少引用的摘要。等待回复时，用户可勾选已经核对完成的事项；原生端核对计划 ID/序号并记录原描述、回复 ID、时间，增加计划版本。模型不能伪造、转移或把旧确认套给新描述。界面和历史上下文区分用户陈述、应用执行、现场验证；未知操作仍走恢复核对，必要验证不会因用户确认自动通过。原生检查点15/15、计划/检查点前端26/26及完整浏览器通过。


6. **M0 精确授权的环境失效已补齐。** 旧实现只按前端连接/终端代次保存完整命令；本批在每次原生分析后同时核对实际目录、账号、环境范围、Shell、原生会话、连接与路由、操作及策略版本。变化或环境未知时清除旧授权，返回原环境也不会恢复；新观测版本但实际环境不变时可以复用该完整命令。先用 7 个调用链用例复现失败，再扩展为 9 个全部通过；明确用户前缀允许项与原生单次批准继续分别判断。
7. **M1 只读程序的特殊参数及长命令审查已补齐。** 本机 Bash 证实 `printf -- '%n'`、宽度/长度变体会给变量赋值；本机临时目录中的 `file -C` 生成了 `magic.mgc`。二者现通过前端与原生规则拦截复用，字面 `%%n`、普通参数及 `--` 后的数据保留原语义。`rg --hostname-bin` 的外部程序能力按 [ripgrep 官方参数源码](https://github.com/BurntSushi/ripgrep/blob/master/crates/core/flags/defs.rs) 核对并标记未知；本机没有 rg，因此仅记源码和策略用例覆盖。审批弹窗补齐最高风险、实际环境、全文展开及风险跳转，修复窄屏溢出，360px 深浅主题浏览器均通过且截图已检查。

8. **M3 Linux 根目录等价证明已收紧。** 相同账号、挂载命名空间和 `/proc/self/root` 字符串不足以排除不同 chroot。现在额外比较当前进程可见的唯一 `/` 根挂载条目摘要；没有可靠根挂载证据时保留当前终端，批准后证据变化则拒绝，不重新选提供方。解析有 256 KiB 预算，不暴露原始挂载参数。依据 [Linux 内核 mountinfo 实现](https://github.com/torvalds/linux/blob/master/fs/proc_namespace.c) 核对了进程根目录相对路径及 chroot 外挂载点省略语义。旧文件环境记录可以反序列化，但不能充当新等价证明；现有完整文件记录的环境范围哈希保持兼容。新增 3 项跨 Rust/Python 用例、15 项文件定向、隔离 SFTP 3 项均通过；真实 SSH 的 SFTP 约 175 秒、当前终端约 25 秒，两条读改恢复路径均通过。
9. **M2 原始输出消费顺序已修正。** 生产事件入口原先先调用显示层，再把原始字符串交给捕获层；显示层可能同步触发 xterm 回调。现先消费完整原始协议，再显示过滤。现有真实 Shell 文件快照用例改经生产事件入口，完整回归及终端浏览器通过，调试开关、相似用户输出、多行输入和迟到标识仍保持预期行为。
10. **M7 无界有效工具循环已补齐。** 之前只有连续无效参数和恢复越界次数限制。每次用户启动/继续现在最多 64 次模型请求、128 次工具调用；达到预算后保留检查点、计划、已观察结果和失败验证，并在下一次批准或派发前停止。不会自动恢复或重放写入。新增 4 项运行时用例覆盖有效计划无限循环、同轮工具超限、最后允许轮正常收尾及失败健康检查不因停止而变为成功。MIG.2 同时补齐了启动失败消息遗漏的 `payloadVersion: 2`。
