# AI Term 响应性能优化方案与实施记录

## 目标与范围

改善主题切换、终端输入及持续输出时的响应，减少 AI 流式消息和文件列表对主线程的竞争。终端浅色主题改为纯白背景、绿色光标。

本次对 `frontend/src`、`src-tauri/src` 的 227 个源文件建立索引，并检索事件循环、定时器、响应式监听、序列化、排序、IPC、主题样式及终端读写；深入检查终端、应用外壳、设置、AI 和文件浏览的高频路径。构建产物、依赖目录不作为业务代码改写。静态扫描发现不等于实测耗时结论，下面分别列出证据与验证办法。

## 已发现的热点

| 路径 | 代码证据 | 本次处理 |
| --- | --- | --- |
| 主题切换 | `applyTerminalAppearance()` 每次写入全部字体参数、主动 refresh、两次安排尺寸测量，字体就绪后强制 PTY resize；非外观设置更新也会触发 | 按有效字体、字号、主题分别比较；颜色变化只更新 xterm 主题，只有字体变化才测量尺寸 |
| 终端持续输出 | 每个 `terminal.write` 回调重复读取屏幕行、识别提示符、更新补全、注册滚动帧 | 字节仍立即交给 xterm；利用 `onWriteParsed` 每帧至多一次处理显示后的辅助工作，合并滚动帧并清理生命周期 |
| 终端尺寸 | 即使行列未变，也替换响应式尺寸对象、调用 resize；可能重复触发父级布局 | 仅在实际行列改变时 resize 和更新尺寸；保留连接/激活时必要的强制同步 |
| Agent 流式思考 | 每个 chunk/reasoning 事件同步复制完整 timeline、steps 并通知 Vue，Markdown 持续重算 | 将显示更新合并为 80ms 一次，状态变化及结束立即保存完整内容；不延迟工具执行、审批或取消 |
| 文件目录 | 每次筛选重新排序，比较器反复调用带选项的 localeCompare；多选逐项 includes 为 O(n×m) | 复用 Intl.Collator，先缓存排序结果再筛选；使用 Set 查找选中路径 |
| 浅色终端 | xterm 使用 `#f6f8fb` 背景和蓝色光标，外围另有灰底 | xterm 和终端外围统一白底，光标为可辨识的绿色，并明确光标字符颜色 |

## 已检查且暂不改动的路径

- SSH 读写已有非阻塞重试与唤醒机制；直接缩短重试间隔会增加空闲 CPU，需真实 SSH 延迟采样后再决定。
- 输入 IPC 已立即派发，只有已有请求在途时才合并后续输入；不增加定时缓冲，不做本地预测回显，避免密码、交互程序和同步输入出错。
- 终端快照已按 200ms 合并发送，内部协议仍接收原始字节；本轮保留此边界，避免影响 SFTP、录制、上下文和探针。
- SFTP 已有目录缓存和并发请求去重；本轮优化本地排序/筛选，不改变服务器读取或缓存有效期。
- 大型 CSS、单个主 JS 包与后台标签渲染列为后续分析项；不在缺少覆盖的情况下删除样式、卸载终端或引入激进代码分割。

## 实施顺序

1. 记录浏览器主题切换时的 resize/尺寸测量次数，以及大量输出时的逐次回调数量，保存基线。
2. 实施终端外观差量更新与浅色配色。
3. 合并终端解析后的显示辅助工作，确保普通按键发送不增加等待。
4. 合并 Agent 流式显示更新，优化文件列表排序和选择。
5. 执行定向单元测试、项目回归、真实 Vue/xterm 浏览器夹具及生产构建，记录优化后结果。

## 验收规则

- 切换颜色主题不引发 PTY resize、字体重设或尺寸测量；不重新创建终端，不改变会话及滚动位置。
- 终端普通键盘输入继续立即进入写入队列；大批输出仍完整、有序，补全、上下键、Ctrl+C、Shell 标记和 Agent 捕获正常。
- Agent 流式文本更新频次有上限，最终消息、工具顺序、取消和错误内容完整；取消后定时器不能覆盖终态。
- 目录自然排序、目录优先、筛选及多选语义保持一致。
- 浅色终端背景 `#ffffff`、光标 `#087f5b`，光标内字符用白色保证对比度。
- 使用合成 IPC 的浏览器结果只证明前端行为；不把它描述为真实网络或服务器延迟的改善。

## 实施结果（2026-09-29）

以上五项实施步骤已完成。输入队列、SSH 重试策略、快照和协议字节传递边界均保持原有方式。

| 同一浏览器夹具场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 10 次主题切换：尺寸测量 | 10 次 | 0 次 |
| 10 次主题切换：PTY resize | 10 次 | 0 次 |
| 10 次主题切换：应用主动 refresh | 20 次 | 0 次（由 xterm 主题更新处理重绘） |
| 1000 个输出分片：逐分片回调 | 1000 次 | 0 次（改用每帧解析完成事件） |
| 1000 个输出分片：解析及两帧观测窗口 | 383.2ms | 33.6ms |
| 单个输入字符进入 IPC | 立即派发 | 立即派发 |
| Agent 同步到达 1000 个文字增量 | 1000 次消息通知 | 首次立即显示，80ms 后一次合并更新 |
| 修改文件查询字符串 | 重新排序匹配结果 | 复用排序，仅过滤 |

测量使用真实 Vue/xterm、单终端、模拟 IPC，输出内容逐行核对未丢失。这是一组可复现的工作负载结果，不是所有机器或真实网络的延迟承诺。主题的两帧观测窗口仍主要落在约 33ms，本次证明的是消除了多余布局和远端 resize，未证明主题端到端绘制时间有显著下降。

额外验证：滚动到历史输出后切换主题仍停留原位置；修改调试开关不测量终端；修改字号会正常更新字号并测量一次；终端属性恢复不会触发无限的写入/解析循环。浅色 xterm、外围及输入法浮层均使用纯白背景，光标为 `#087f5b`。

1. 在独立测试端口启动前端开发服务器，例如 `npm run dev -- --port 5174`。

3. 在 `frontend` 运行 `npm run test:performance-browser`；可通过 `AI_TERM_PERF_APP_URL`、`AI_TERM_PERF_CDP_URL` 指定地址。
4. `outputs/performance-2026-09-28/before.json`、`after.json` 和截图保存本机采样；`unit-tests.log`、`build.log` 及 `terminal-regression/` 保存本次验证产物。
