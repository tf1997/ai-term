# AI 上下文与 token 开销

AI Term 使用 OpenAI 兼容的 Chat Completions 接口，每次请求仍需携带模型推理所需的上下文。减少 HTTP 请求体、减少输入 token 和提高缓存命中率是不同的指标；缓存也不代表输入 token 免费。

## 当前优化

- **按体积生成持久摘要。** 未压缩的对话达到 8,000 字符时，将较早的消息并入摘要，近期原文以 4,000 字符为目标，至少留出最近四条消息不参与摘要并保持问答边界。原有的条数触发条件仍保留：最近 16 条之外再积累 8 条消息。普通对话和 Agent 成功结束后共用这一流程。最终请求仍受后端原有的近期对话 8,000 字符、单条 3,000 字符限制。
- **压缩请求本身也有预算。** 每条来源消息最多 1,500 字符，一批最多 12,000 字符，长消息保留开头和结尾并标注省略。批次从最早的未压缩消息开始，摘要截止 ID 只推进到实际送出的消息；剩余历史留待后续批次处理。Agent 摘要包含命令、状态、退出码及结果片段，敏感步骤的命令和输出不进入这些补充记录。
- **摘要可跨会话恢复。** 摘要和截止消息 ID 继续保存到 SQLite 的 `workspace_sessions`。恢复后使用摘要与截止点之后的近期消息。失败或过时的后台响应不会覆盖较新的摘要；重试摘要覆盖范围内的旧问题时，不使用包含后续结论的摘要。
- **完全相同的工具输出只携带一份。** 在每次 Agent 请求内保留首次出现的长输出，其余相同输出引用前面的工具结果。只替换 `output` 字段，执行状态、退出码、耗时、截断标记和工具调用关系保持不变。不同输出及不足 256 字符的短输出保持原文。引用每次根据当前请求重建，不会指向已被压缩掉的原文。界面与数据库中的执行记录不受影响。
- **减少历史改写。** Agent 轮次仍在超过 24,000 字符时触发压缩，但以 18,000 字符为目标留出增长余量；最近六个协议轮次保持原样，因此极大近期输出下不保证达到目标。随后未再次超过触发阈值时，历史前缀不变。系统提示词与历史摘要分开为消息，工具定义也保持稳定。

这里的字符预算是跨模型的上下文保护措施，不是精确 tokenizer 计数。生成摘要本身也需要模型请求；较大的历史通常需要在后续请求中复用摘要才能摊平这部分成本。标题请求此前已限制为问题 600 字符、回答 900 字符，不会重发终端日志。

## 验证与衡量

`npm run test:ai-context` 验证压缩批次、恢复、并发、会话切换、重试、Chat/Agent 完成后的摘要写回，以及轮次压缩的余量和近期证据保护。该测试文件也已纳入 `npm run test:scripts`。`cargo test --lib domain::ai::` 验证实际发送的消息结构、引用完整性及缓存前缀稳定性。

重复输出测试使用 4,500 字符的日志：第一份保留原文，第二份输出改为不足 100 字符的引用。这是特定重复内容的字符减少量，不是整个请求或真实账单的 token 节省比例。现有 20 步回放测试比较 24k 软预算与 80k 上限，同样只报告回传字符数，不能把原有优化的收益全部归于本次改动。

真实效果应比较同类任务的请求次数、累计输入和输出 token、缓存输入 token 与延迟，并计入标题和摘要请求的成本。目前会话用量来自普通回答及 Agent 请求的网关 `usage`，后台标题和摘要请求尚未计入该显示值。缓存的最低长度、启用方式、有效期及计费取决于模型和网关；本次未向任意兼容网关添加专有缓存字段。

## 公开资料

- [Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)：按 token 阈值触发历史压缩、单个工具输出的历史预算。这里借鉴预算管理方式，字符限制仍按 AI Term 的现有协议实现。
- [OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching)：保持稳定指令与工具定义，追加消息，减少改写既有上下文；压缩会使旧缓存需要重建。不同模型的缓存断点规则不同。
- [Claude Code 成本管理](https://code.claude.com/docs/en/costs)：自动压缩、缓存、限制工具输出、主动管理上下文，以及将压缩本身的开销计入评估。

后续可在明确所用模型与网关能力后增加实际 tokenizer 预算、显式缓存断点、后台请求用量归集和独立摘要模型。仅改用服务端会话 ID 并不自动消除历史上下文的计费。
